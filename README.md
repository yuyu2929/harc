## 它解决什么问题

栅格数据（地类图、DEM、气象格网、遥感影像）的存储一直有一个没有同时被满足的"不可能三角"：

> **压缩率高 + 随机访问 + 局部可更新**，三者只能取二。

| 现有方案 | 压缩率 | 随机访问 | 局部更新 |
|---|:---:|:---:|:---:|
| 整幅 zlib / GeoTIFF(Deflate) | ✅ 好 | ❌ 整图解压 | ❌ 改一点、写全图 |
| 分块 zlib（COG / Zarr） | ⚠️ 块界限制 | ✅ tile 级 | ⚠️ 固定 tile 整块重写 |
| **Esri LERC** | ✅ 好（噪声场景最强） | ✅ 块级 | ⚠️ 块级重写 |
| PNG（预测+熵编码） | ✅ 好 | ❌ | ❌ |
| 游程编码 | ⚠️ 破碎数据膨胀 | ⚠️ | ⚠️ |
| **HARC** | ✅ **内容自适应**（4/5 数据集领先 LERC，纯噪声落后约 15%） | ✅ **内容自适应块级** | ✅ **改 1 像素 = 重写该叶子 + 拷贝一次码流** |

### HARC 的三个企业级能力

1. **局部更新（Update-in-Place）**：修改一个像素只需重新编码它所在的叶子（默认 ≤ 32×32），
   其余节点按原字节保留。对高频更新的栅格服务（实时热力图、水位/温度格网、在线协同编辑的底图），
   相比"整图解压再整图重压"是数量级的下降。

   > **实现与代价（v3）**：默认单树格式改一个像素要**重编整棵树**。
   > 传入 `chunk=256` 可启用 **v3 分块容器**：整幅切成 256×256 的独立子树，
   > `set_pixel` 只重编它所在的那一块，其余块的字节原样搬运。
   >
   > 实测 1500×1500：单树 2.63 s → 分块 **0.21 s（12.6×）**，体积仅增加 0.3%。
   > 注意写入量仍是 **O(文件大小)**（要把整个文件写回），降的是**压缩 CPU**，
   > 不是磁盘 I/O。真要"只写几个字节"，需要页式存储或固定槽位，见路线图。
2. **区域随机解码（Region Random Access）**：`decode_region(r0, r1, c0, c1)` 只解析窗口路径
   上的节点，窗口外只跳过字节不解码——给瓦片服务/预览缩略图用，无需预切图。
3. **内容自适应压缩**：编码器在四叉树每个节点上"现场竞赛"三种叶子编码（同值 / 游程 /
   中值预测差分+熵编码），谁小用谁。大块均质区压到 **十几字节/整幅**（v2 头部多了 dtype 与
   CRC32，最小码流约 17 字节），破碎纹理自动交给预测器。

## 快速上手

```bash
pip install .            # 或直接把 harc.py 拷进项目，仅依赖 numpy
```

```python
import numpy as np
from harc import encode, decode, decode_region, set_pixel

dem = np.load("terrain.npy")            # 任意二维整数数组

blob   = encode(dem)                    # 无损编码
back   = decode(blob)                   # 全图解码（逐元素相等保证）
assert np.array_equal(back, dem)

window = decode_region(blob, 100, 200, 300, 400)   # 只解 100×200 的窗口
assert np.array_equal(window, dem[100:200, 300:400])

blob2  = set_pixel(blob, 77, 233, -999) # 局部更新：只重编 1 个叶子

# 高频更新场景：改用分块容器，改像素只重编它所在的块
blob3  = encode(dem, chunk=256)
blob3  = set_pixel(blob3, 77, 233, -999)   # 只重编 1/块数 的数据
dem[77, 233] = -999
assert np.array_equal(decode(blob2), dem)
```

## 它是怎么做的

三层架构，每一层吸收一类经典编码的长处：

```text
① 结构层   四叉树递归分解 —— 均质区域大块合并（四叉树编码的长处）
② 叶子层   节点级三选一竞赛，实测字节数取最小：
             UNIFORM  整块同值 → 只存 1 个增量值          （块编码思想）
             RLE      行内长游程 → 游程对编码             （游程编码思想）
             PRED     中值边缘预测差分 + 动态位宽 + zlib  （PNG/LERC 思想）
③ 熵层     全部整数 zigzag + varint；RLE/PRED 载荷带长度前缀（可跳过、可替换）
```

## 适用边界（请务必阅读）

- 目前支持**二维整数数组**（int32/int64 值域）；浮点请先量化，多波段/多维在路线图。
- 无损编码——不追求极致压缩率时，有损场景（量化 + PRED 残差截断）是路线图项。
- 参考实现为 Python；格式本身是语言无关的，码流规范见 `docs/`。
